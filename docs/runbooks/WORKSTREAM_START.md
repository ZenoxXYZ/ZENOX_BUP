# Workstream Start

1. Confirm the workstream exists in approved `plan.md` and has prerequisites.
2. Allocate responsibilities from the Challenge Profile, Minimum Winning Scope, workstreams, dependencies, risk, and available humans—not from team size or fixed software titles.
3. Record objective, Critical-Proof-Path relevance, one accountable Primary Owner, optional contributors or specialist owners, optional Integration Owner or Verification Owner where useful, dependencies, governing Interface / Assumption Contracts, required evidence, integration applicability, and exit criteria in `execute.md`. Record Golden-Path relevance only for Product Build work.
4. Synchronize `main`.
5. Create one bounded branch.
6. Decide whether one human's concurrent mutable work requires dedicated worktrees; they are not mandatory.
7. Launch a Builder planning pass; do not implement until human approval.
