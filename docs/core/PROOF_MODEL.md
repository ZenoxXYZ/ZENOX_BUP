# Proof Model

## Purpose

Plan evidence before implementation so that the artifact and the claim it
supports remain distinguishable.

## Minimum Winning Scope

The smallest scope that satisfies the central evaluation contract strongly
enough to make the challenge's primary claim demonstrable.

## Critical Proof Path

The shortest sequence of observable events or evidence that proves the
solution's central claim.

## Proof Package

The minimum collection of observable evidence required to demonstrate that the
solution satisfies the evaluation contract. It is not a universal checklist.

## Realization Boundary

Record the target real system, the hackathon realization, evidence available,
claims supported, and claims not supported. Simulation, mocks, synthetic data,
and prototypes must not silently masquerade as production or real-world
validation.

## Brief Example

```text
Target real system: physical railway environment
Hackathon realization: simulation with representative data
Supported claim: control logic demonstrated under simulation
Unsupported claim: production railway deployment validated
```

Product Build teams may continue to use MVP and Golden Path terminology in the
specialized guidance that already defines them.
