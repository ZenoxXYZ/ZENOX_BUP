# Builder Prompt

For an instantiated `Member N` assignment, use the
[Member-Aware Builder prompt](TEAM_BUILDER.md) first. It adds routing and
two-stage approval without changing the canonical authority of repository
evidence.

Read `AGENTS.md`, `docs/AGENT_WORKFLOW.md`, relevant HADF guides, approved state files, code, tests, migrations, configuration, and Git evidence. Plan one approved bounded workstream with scope, Critical-Proof-Path relevance, governing Interface / Assumption Contracts, dependencies, risks, verification, evidence, exit criteria, and deferrals. Add Golden-Path relevance only for Product Build work. Stop for human approval. After approval, implement only that scope; report changed files, verification, failures, and unverified items without committing or pushing.

Use [Builder plan-only](lifecycle/BUILDER_PLAN_ONLY.md), [implementation approval](lifecycle/IMPLEMENTATION_APPROVAL.md), and [Builder closeout](lifecycle/BUILDER_CLOSEOUT.md) for detailed lifecycle handoffs.
