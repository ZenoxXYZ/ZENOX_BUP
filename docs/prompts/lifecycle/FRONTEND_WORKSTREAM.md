# Frontend Workstream Prompt

> **Product Build specialization.** Use after the [Product Build playbook](../../playbooks/product-build.md) applies.

## Use

After UI requirements and relevant backend/API contracts are approved and stable enough.

```text
Read AGENTS.md, the Builder workflow, the full-stack and API-contract guides, approved problem.md/plan.md, current contracts, tests, and evidence. Plan the smallest frontend capability or slice: required views/components, state model, real API calls, loading, empty, success, validation, failure, recovery, Golden-Path relationship, accessibility/basic polish, API base URL configuration, deployment implications, verification, and risks.

Keep business/decision logic in the backend. Identify missing or incompatible contracts before implementation. Frontend does not wait for every backend workstream. Stop for human approval.
```
