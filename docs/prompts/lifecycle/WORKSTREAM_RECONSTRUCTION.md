# Workstream Reconstruction Prompt

## Use

After a meaningful workstream is implemented and verified. In member-aware
execution, this is the Feature Reconstruction: one workstream's implemented
reality. It is distinct from final whole-project reconstruction.

```text
Do not modify files, configuration, dependencies, migrations, tests, project-state files, commit, or push. Read AGENTS.md, the Builder workflow, approved state files, phase/review records, code, tests, migrations, configuration, and Git evidence. Teach [WORKSTREAM NAME] from actual repository evidence.

Cover requirement, objective, Critical-Proof-Path relationship, design and rationale, important artifacts/layers including N/A decisions, governing Interface / Assumption Contracts, dependencies, integration, verification/evidence, meaningful bugs/fixes, assumptions/deferrals, limitations, exit criteria, and a 30–60 second judge explanation. For Product Build work, also cover Golden-Path relationship and trace user action through frontend, contract, route, validation, service/logic, persistence, response, UI, and verification. Ask whether the human can explain the workstream, then stop.
```
